Direct anime streams.
Zero browser overhead.

A lightweight TypeScript resolver for direct video URLs. Built entirely on raw HTTP requests and light DOM parsing—no heavy headless browser required. Fully tested with live E2E video frame capture.

Get started → View on GitHub ↗
example.ts
import { HttpClient, AllmangaProvider } from 'ani-sdk';

const http     = new HttpClient({ timeoutMs: 25_000 });
const provider = new AllmangaProvider(http);

const hits     = await provider.search('Frieren');
const eps      = await provider.fetchContentUnits(hits[0].id, 'sub');
const stream   = await provider.resolveStream(eps[0].id);

// streams[] sorted best-first; iterate if the top one 4xx's
console.log(stream.streams[0].sourceUrl);

Embed extractors are first-class.

Stateless classes that take an HttpClient and an embed URL and return IVideoPayload[]. Use them inside a provider or on their own.

Mp4UploadExtractor

Follows the mp4upload.com → www.mp4upload.com redirect, parses the player snippet, and returns the direct /video.mp4 URL.

BloggerExtractor

Strips FdrFJe/cfb2h from the embed page, calls the WcwnYd RPC on Google's batchexecute endpoint, and pulls the best MP4 (preferring itag=22).

GenericHlsExtractor

Best-effort scrape of an embed page for an .m3u8 or .mp4 URL with a strict path component anchor — no false positives from domain substrings.

VidstreamingExtractor

Legacy Gogo encrypt-ajax.php flow: derive AES key/IV from container class names, decrypt data-value, request the AJAX endpoint, decrypt the source list.

Three-step pattern, every provider.

search → fetchContentUnits → resolveStream. The IDs are opaque strings the provider uses to thread state between calls.

Provider · gogoanime simple.ts 
import { HttpClient, GogoanimeProvider } from 'ani-sdk';
import { DOMParser as LinkeDomParser } from 'linkedom';

if (typeof globalThis.DOMParser === 'undefined') {
  (globalThis as any).DOMParser = LinkeDomParser;
}

const provider = new GogoanimeProvider(
  new HttpClient({ timeoutMs: 10_000 })
);

const hits   = await provider.search('One Piece');
const eps    = await provider.fetchContentUnits(hits[0].id);
const stream = await provider.resolveStream(eps[0].id);

for (const s of stream.streams) console.log(s.sourceUrl);
Extractor · standalone blogger.ts 
import {
  HttpClient,
  BloggerExtractor,
} from 'ani-sdk';

const blogger = new BloggerExtractor(new HttpClient());

// Hand it any blogger.com/video.g?token=… URL.
// Returns IVideoPayload[] best-first; empty array if Google
// flagged the token as dead.
const streams = await blogger.extract(
  'https://www.blogger.com/video.g?token=AD6v…',
);

for (const s of streams) {
  console.log(s.quality, s.sourceUrl);
}

Tests run against the real internet.

Mocks let scrapers rot. Each E2E test goes all the way to ffmpeg and asserts the screenshot is > 1 KB — that's how we know the URL is still actually playable.

What happens

For every provider: search, pick a mainline title, walk episodes, resolve a stream. The screenshot helper then iterates the candidate list, probing each URL with a Range GET (Content-Type + MP4 ftyp magic) before either piping it through ffmpeg or downloading an HLS segment ~5 s in.

Why no skipping

A test that silently skips when the network's flaky becomes a test that always passes for the wrong reason. If a provider can't deliver a playable URL right now, the suite fails. Providers that can't deliver at all are deleted, not muted.

Install.

Node 20+ for native fetch and crypto.subtle. ffmpeg on PATH if you want to run the E2E suite.

Package manager
npm npm install ani-sdk linkedom
pnpm pnpm add ani-sdk linkedom
yarn yarn add ani-sdk linkedom
bun bun add ani-sdk linkedom

linkedom is needed because most providers scrape HTML and Node has no built-in DOMParser. Register it on globalThis before you call any provider.
